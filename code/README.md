## 两种模式

首页 → **Meet your creature** → 选择三种形态、八种主题色 → 选择：

- **Start interaction**：点击后才申请一次摄像头及麦克风权限，加载本站 Face Landmarker、ml5 HandPose 和 Pose Landmarker；只使用真实音频、面部、手部和上半身关键点信号。
- **Try demo**：独立的模拟模式，不申请设备权限、不加载模型。保留声音、表情、手势及身体控制，明确标注 Demo。

所有非首页界面均保留 **← Home**。Live 中 **End interaction** 和 Home 都会停止所有媒体轨道、关闭 AudioContext、终止识别 Worker。再次开始重新建立一次会话。取消待决权限请求后，若浏览器稍后返回媒体流，也会立即停止其轨道。

Live 的 **Hide preview** 仅隐藏镜像画面，识别继续。工具栏 **Microphone** 会禁用麦克风轨道并清空声音输入，重新开启后再次校准。设备意外断开、权限拒绝、人脸模型失败显示英文错误及 **Try again**，同时清理会话；手势和身体模型失败则只清理各自任务，保留其他互动，并分别提供重试。页面进入后台暂停分析并清空旧表情，返回时重新校准麦克风；已完成的中性面部校准保留，尚未完成的校准中断。离开页面通过 `pagehide` 清理设备。

## 信号处理

### 麦克风

- Web Audio Analyser 获取时域样本并计算 RMS，麦克风采样不直连扬声器（无返听）；Music / Sound Effects 使用独立播放节点与 AudioContext。
- 开始或 **Recalibrate room noise** 后约 1.3 秒采样，使用较低分位估计底噪；请在这段时间保持安静。
- **Sensitivity** 范围 0.5–3.0。底噪门限、快速上升/缓慢释放的指数平滑共同驱动粒子颤动与波纹。
- 受惊必须超过绝对响度门限、底噪倍数和近期音量基线，同时出现明显上升。
- 一次突增后至少冷却 3 秒，并需连续安静约 0.4 秒重新准备；持续大声不会周期性重复触发。

### 面部动作

- 使用真正的 **MediaPipe Face Landmarker**，`VIDEO` 模式、单张人脸、输出 blendshape 分数；CPU WASM 在独立 Worker 中执行，最多约 12.5 次/秒，最多一帧在处理中。
- 微笑保留左右 `mouthSmile` 的原有映射。悲伤外观使用 `mouthFrownLeft`、`mouthFrownRight` 和 `browInnerUp`，名称已与 [MediaPipe 官方 blendshape 列表](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/cc/vision/face_landmarker/face_blendshapes_graph.cc) 核对。`_neutral` 不覆盖其他分数，不将模型分数当作心理情绪。
- 修正旧算法多次相乘造成的过度抑制：旧算法在左右 frown 都为 .25、inner brow 为 .20 时，组合分数约 .186，过不了 .32 阈值。现在提供两条证据路径：平均 frown ≥ .11、弱侧 ≥ .055 且 inner brow ≥ .13；或平均 frown ≥ .24、弱侧 ≥ .10。根据幅度加权评分，再经平滑后 sad 分数 ≥ .28 才进入；不会仅因不笑、闭眼或低头判为悲伤。
- 张嘴 ≥ .45 时，悲伤路径必须同时满足更强的 frown（平均 ≥ .20）和 inner brow（≥ .23），减少说话、唱歌时嘴形变化误触发。有效微笑、惊讶仍会抑制悲伤，切换竞争余量从 .14 降为 .08，避免残留微笑长时间阻挡新表情。此规则不能保证所有唱歌表情均不误判。
- 惊讶需要 **外眉抬起与眼睛睁大同时出现**。`jawOpen` 只增加少量权重，单独张嘴不会触发惊讶。
- 分类分数平滑时间常数约 167 ms，smile 候选保持 300 ms、surprise 400 ms、sad 650 ms、neutral 400 ms，保持阈值 .18。悲伤外观另有连续视觉通道，弱证据无需先赢得完整状态即可渐蓝、减速；更强证据再进入完整状态，详见下方 2026-10-22 更新。沿用蓝色渐变、缓慢下沉、聚拢和渲染平滑。Demo 的强度控制保持原样。丢失人脸、结果间隙超过 500 ms 或切到后台都会清空连续表情证据；已有校准保留，后台及迟到帧不参与校准或表情累积。
- 这些是面部动作的近似映射，不能识别真实心理情绪。光线、角度、眼镜和个体差异会影响效果，需要真人调试。

**Expression diagnostics** 默认折叠，在 Live 控制面板中展开。显示原始分数（缺失为 `—`）、扣除中性基线后的 frown / brow、平滑证据、最终及候选表情、候选保持时间、实际判断阈值、动画强度。面板每 250 ms 更新，折叠时不刷新表格；动画强度不是识别置信度。

### 连续悲伤外观与最新真人数据（2026-10-22）

新增真人诊断数据保存在 `qa/fixtures/expression-live-summaries.json`，包含两组各 12 帧、约 2.8–2.9 秒的均值／范围、最后一帧、校准基线和噪声。这些是用户提供的聚合统计，**没有原始有序帧**，测试中重复均值或最后一帧不等同于真人视频回放。测试值不作为产品个人默认值。

实际瓶颈已可定位：Sad 标签的左右 mouthFrown 均值 .0296 / .0273，中性 .0046 / .0040，两组嘴部取值范围在这些窗口中不重叠；因此不是模型完全没有响应。但 sad 内眉均值 .0204，比中性 .0238 还低，更低于校准基线 .04005，旧相对路径强制要求内眉增加 .018，会直接将整条路径置零。嘴角又未到绝对路径 .11，导致分类证据为零，**与 neutral / smile 竞争或 650 ms 确认时间无关**。旧校准与后来中性样本的眉部分数也有明显偏差，不能把两段差异全归为表情。

- 保留原有强表情及抬内眉路径，不整体降低 .28 进入阈值或 650 ms 状态确认时间。
- 增加“嘴角双侧变化＋眉毛下压＋外眉收落”路径，允许内眉不抬起。这条路径仍需要嘴部和两类眉形证据共同出现；没有微笑、闭眼、视线或头部姿态都不作为正向证据。
- 连续通道使用有符号的个人基线差值、特征平滑和独立噪声底线（默认至少 1.5 倍校准噪声）。抬内眉通道最小 mouth / weak-side 变化 .0015 / .00075；收眉通道更严格，为 .006 / .004；眉毛下压最小 .0025、外眉收落 .0035。低于噪声的证据不会因为等待而变成有效。重新校准时还直接测量左右均值及眉形对比的噪声，避免把所有成对信号都按最吵的一侧估计。
- 当前帧必须真的具有联合特征，才累积持续时间；短脉冲不会靠滤波残留不断累积。按新鲜结果实际时间计算，超过 500 ms 的间隔清空连续证据。持续约 .35 秒后开始渐入，随后约 .8 秒逐渐加强；弱证据最多输出 .42 动画强度，类别仍可能是 Neutral。中性类别不会把这条视觉通道清零。
- 收眉路径要确认完整状态，还需连续约 1.4 秒、嘴部组支持 ≥ .6、眉形组支持 ≥ .35、组合分数 ≥ .28，再通过原有的状态确认。视觉强度随平滑分数连续变化、额外平滑至粒子；完整状态不再直接将强度硬抬至至少 .5。恢复平静后自然退回主题色；丢脸、后台或过期结果清空识别输出，渲染继续自然恢复。
- 微笑、惊讶、张嘴保护和音频策略保留。说话／唱歌仅张嘴不触发悲伤；单嘴角、仅眉部、仅不笑、眨眼或向下视线在合成反例中均不成立。真实低头、皱眉思考等情况下的 blendshape 偏差仍需要真人反例测试。

面板新增 **Gradual sad-look**，显示路径、连续证据、实际传入粒子的强度、联合特征是否新鲜、持续时间、各组支持度及噪声底线。弱反应存在时主状态显示 **Gradual sad-look response**，不把动画强度当作识别概率。采集 Neutral 后会检查其与当前校准是否明显偏移，提示重校准但**绝不自动改变基线**。采样导出新增原始分数和连续输出的逐帧 timeline，后续可真正检查时间稳定性，而不只依赖均值。

`node code/qa-continuous-sad.cjs` 检查这次真人数据的旧门槛失败点、聚合值／最后一帧回放、弱反应与完整状态分离、噪声、瞬时信号、竞争、丢脸、4 / 12 / 30 Hz 和校准偏移提示。报告为 `qa/continuous-sad-report.json`。`node code/qa-expression-browser.cjs` 使用虚拟设备和显式替换的分数，检查连续强度是否确实进入蓝色、减速和聚拢，并覆盖原有微笑、惊讶与采样流程。这些检查不等同于本次修改后的真人效果验证。

目前这两组嘴部分数已有可用差异，因此沿用 MediaPipe，不新增模型依赖。若后续在同一光线和校准下的多组有序样本仍与中性明显重叠，可另做本地模型对比：使用 [ONNX Model Zoo 的 FER+ 表情分类模型](https://github.com/onnx/models/tree/main/validated/vision/body_analysis/emotion_ferplus) 与 [ONNX Runtime Web](https://onnxruntime.ai/docs/tutorials/web/)，复用现有人脸范围裁切 64×64 灰度输入，保留 MediaPipe，不再开启摄像头或做人脸检测。需要额外固定版本的运行库、匹配 WASM 和 ONNX 模型；官方模型约 34 MB，int8 版本约 19 MB，另计运行库。建议先在 Worker 中每秒 2–4 次、单任务、不堆帧地试用。这是测试频率建议，**不是实测性能**；手机会增加下载、内存、CPU 消耗和发热，必须与现有手势／身体任务一起测量，也不能保证能区分所有轻微表情。当前未下载、未安装或接入此候选模型。

### 根据五张真人诊断截图调整（2026-10-19）

用户提供了平静、轻微悲伤、惊讶、微笑、张嘴说话五张诊断截图。数值转录到 `qa/fixtures/expression-screenshots.json`，不会作为产品中的个人默认基线。惊讶截图的外眉均值 .1255、睁眼 .030 低于原来的 .22 / .15 门槛，归一化后都为零；悲伤的 frown 均值 .010 低于 .11 门槛。两者 mouthSmile 都为零，因此截图中的失败不是微笑覆盖，而是进入特征组合前就被门槛挡住。截图能证明这些帧的模型输出发生了变化、最终仍为 Neutral；不能证明后续时间稳定性或所有真人动作的分布。

保留上面的较强表情路径，同时增加显式中性校准后的相对路径。微笑公式保持原样。每次进入 Live 后，正对镜头，放松眉毛和嘴角，点击 **Calibrate neutral** 约两秒；程序采集全部 12 个相关分数的中位数，以及 MAD 和 10–90% 分位范围一半中的较大值作为噪声。有效变化门槛取下述最小值与四倍对应噪声的较大者。基线不会随着正在做的表情自动漂移，校准也不根据心理情绪作判断。校准后的较强惊讶路径同样扣除个人基线，避免较高的静态眉眼分数直接触发。

- **相对惊讶 A**：外眉均值增加 ≥ .025、弱侧 ≥ .012，睁眼均值增加 ≥ .012、弱侧 ≥ .007；嘴巴可以闭合或轻微张开。
- **相对惊讶 B**：内眉增加 ≥ .045，外眉均值 ≥ .018，睁眼均值 ≥ .008，张嘴增加 ≥ .12；同样要求外眉/眼睛弱侧的变化。加权组合强度取代多次相乘压低微弱分数；两条路径都不能单凭张嘴触发。说话截图虽然内眉和嘴巴也变化，但睁眼增量不足，仍保持 Neutral。
- **相对悲伤外观**：嘴角下垂均值增加 ≥ .004、弱侧 ≥ .003，内眉增加 ≥ .018，再要求眉毛下压均值增加 ≥ .010，或内眉增量减外眉增量 ≥ .035。嘴巴原始开度 < .25 且增量 < .10。嘴角、内眉、眉形必须共同变化，之后仍需平滑分数越过 .28 并保持候选 650 ms。不是凭不笑、闭眼或低头判断；这些精细阈值需要真实连续视频继续复测。

这一位用户的轻微悲伤相对平静为：frown 均值 +.008、弱侧 +.006、内眉 +.033、眉毛下压均值 +.021、内外眉对比 +.074；惊讶外眉 +.053、睁眼 +.0185。截图值回放已验证新路径能接受这两组值，且微笑、平静及张嘴说话的结果保留。**截图数值被重复作为静态序列回放，校准噪声在此理想序列中为零，绝不等同于修改后的真人摄像头测试。**另用合成噪声验证有效门槛会随波动升高。

面板为 smile / sad / surprise 分别显示特征条件失败、分数不足、竞争抑制、候选确认时间和丢失状态；新增有符号相对变化、当前有效变化门槛和通过的路径。动画栏显示 `target`（传入粒子的表情强度）与 `rendered`（渲染平滑后的强度）、颜色、速度和舒展度，可区分判断与动画响应。`browDownLeft/Right` 参与新的悲伤眉形路径；缺少任何一项相关分数时，相对路径不会运行，面板会提示。

真人采样步骤：刷新本地预览 → Start interaction → 展开 Expression diagnostics。选择 **Expression you are trying** 标签，然后点击 **Sample for 3 seconds** 并保持该表情。先采 Neutral，再采 Slight sad-looking expression、Surprise、Smile 和 Speaking / singing。各标签可重新采样覆盖；保持同一光线、距离和会话。完成后用 **Copy samples** 将文字贴回开发对话；优先给平静与惊讶两组也可以。剪贴板不可用时，直接复制下方文本框。

导出记录包含原始分数均值/范围、相对 Neutral 样本的变化、实际用于分类的中性校准基线、最后一帧的判断理由及动画传递数值。`intended` 是用户选择的动作标签，不能当作模型判定；采样时的 Neutral 对照仅用于诊断，不会自动更改分类器基线。需至少六个新鲜采样点且跨度两秒；人脸丢失、后台或正在校准会中断采样。数据仅留在当前标签页，无照片、无音频、不会自动上传；Home / End interaction 清除。重新校准后建议重新采集全部对照标签。

自动测试覆盖诊断原因、截图值回放、合成分数采样与相对值、动画传递、剪贴板失败时手动复制及丢脸取消。浏览器测试使用真实本地模型、虚拟摄像头与显式替换的分数，**不代表修改后真人惊讶或轻微悲伤的准确率**。下一步需真人复测，尤其是连续说话、唱歌、低头、光线变化和不同人的自然表情，必要时再提供三秒采样数据。

**Calibrate neutral** 至少采集 12 帧连续稳定样本；明显微笑、张嘴、分数波动或超过 350 ms 的采样间隙会重新等待稳定窗口，8 秒无法完成会提示重试。人脸丢失或后台切换会中断未完成的校准；已有基线和噪声估计保留。**Reset calibration** 清除基线；Home / End interaction 自动清除会话基线。无校准时保留较强表情的判断；轻微表情请先校准，光线或镜头角度改变后重做。

真人简测：刷新页面，进入 Live，展开面板并完成中性校准；分别做轻微悲伤、惊讶（可仅轻微张嘴）、微笑，各保持 1–2 秒，中间恢复平静。对照 Raw scores、相对变化、通过路径、Final 与蓝色/紫色行为，再检查张嘴哼唱、闭眼和低头。若仍不响应或误判，请采集三秒数据，尤其保留校准噪声与实际门槛；不同人、弱光、眼镜及实体手机仍需现场验证。

两种模式共用既有粒子颜色、位移、恢复过程、熟悉度和音效调度；识别与 Demo 输入源严格互斥。四类已确认音效已接入，未使用在线 ElevenLabs 服务。Capture 只下载粒子图像，不含摄像头。

### 手势

- 使用固定 **ml5 1.4.0 HandPose**，TFJS runtime、单手、lite 模型。直接复用 `#camera` 的媒体流，将帧传入独立 Worker，完整画面等比例缩小到最长边 320 像素后分析；不会再次申请摄像头。使用官方 `detect(ImageData)`，未开启库内连续循环，不需要 p5.js 或 DOM 模拟。
- 手腕和四个指根的平均位置作为掌心；`1 - x / width` 与镜像预览一致，`y / height` 映射到粒子画布的实际 CSS 尺寸。预览使用 contain，保证完整画面可见；竖屏和横屏均不裁剪关键点来源。
- 由四指伸展比例及弯曲程度计算张开程度，优先使用模型 3D 点。位置和张开程度指数平滑，有置信度进入/保持阈值、死区、两帧确认、异常跳点过滤。手离开后保留最后坐标并逐渐减弱跟随和舒展。
- 速度按实际取帧时间与视频最长边归一化。连续两帧快速移动才触发退缩；至少冷却 3 秒，并需约 0.5 秒慢下来重新准备。连续挥动只触发一次，熟悉程度不减。
- 最多约 8 次/秒单次检测；根据推理耗时延长间隔，每次结果后留出休息时间，始终只允许一帧在处理中。粒子在主线程 requestAnimationFrame 绘制；模型加载和推理均在独立 Worker，避免软件计算阻塞画面。实际识别频率由设备能力决定，需要实体手机复测。
- Home / End interaction 停止调度、终止手势与人脸 Worker、释放摄像头和麦克风；迟到帧也会丢弃。再次进入创建单个新手势任务，上一任务已经释放。隐藏页面不提交新检测，旧结果不会写回。
- 手势加载/检测失败显示独立英文提示与 **Retry hand tracking**，不会停止表情和麦克风。无模拟兜底。只看到手时会唤醒运动；熟悉程度的时间增长仍需人脸在场。

官方接口：[HandPose 文档](https://docs.ml5js.org/#/reference/handpose)、[ml5 HandPose 源码](https://github.com/ml5js/ml5-next-gen/blob/main/src/HandPose/index.js)。

本地资源：`vendor/ml5-1.4.0/ml5.min.js`（内含 TFJS **4.22.0**）、`vendor/tfjs-wasm-4.22.0/`（同版本官方 ES2017 加载器及 WASM）、`models/handpose-detector/` 与 `models/handpose-landmark/`（各包含 `model.json` 和 `group1-shard1of1.bin`）。WASM 加速在独立 Worker 中运行，单线程，无需配置跨域隔离；运行前检查 TFJS 版本一致性。ES5 后端无法继承 ml5 包内的原生类，因此使用官方 `tf-backend-wasm.es2017.js`。

### 身体姿态

采用 **MediaPipe Pose Landmarker Lite**：复用现有 `@mediapipe/tasks-vision` **0.10.14** JS/WASM，新增长度约 5.8 MB 的官方 `lite/float16/1` 模型，不引入另一套前端库。保持原有 ml5 HandPose，不用身体模型替代手势。

- 一个 `#camera` 视频流供三种视觉任务取帧。人脸独立 Worker 保持响应，手势和身体各有一个 Worker，共用单个推理时段：忙时丢弃新帧，不建立等待队列。手势最多约 8 Hz、身体最多约 6 Hz，依耗时自动降频，并在结果后留出间隔；实际频率取决于设备。
- 初次依次启动人脸、手势、身体模型。身体加载不占用推理时段，因此下载缓慢或失败不会阻塞已有互动。身体最多处理一帧，输入保留长宽比并缩小至最长边 384 像素，单人、无分割遮罩。
- 肩、肘、腕先按视频尺寸转为像素，采用肩宽归一化位移和关节变化。进入/保持置信度门限为 0.65/0.5，同时检查可见度、存在概率、是否在画面内及最小肩宽。仅脸部近景、肩膀猜测不足以激活身体互动。
- 以进入画面时的肩膀中心作为摇摆基准，左右方向与镜像预览一致。双臂展开或抬起提供上浮和舒展；单臂丢失不凭空推测另一侧。运动强度来自真实经过时间内的身体平移及相对关节速度，距离变化与异常突跳会过滤。
- 身体摇摆是围绕手势目标的小幅偏移；手在场时削弱身体位置偏移，握拳时削弱身体扩张。身体只控制整体摇摆、上浮、旋转、流动与舒展，不触发受惊；颜色、声音波纹继续独立叠加。
- 停止运动后逐渐恢复；短暂识别失败有容差，超过约一秒无新可靠结果则平滑退回自主状态。身体在场可以唤醒运动；熟悉程度仍按人脸在场的实际时间增长，不改变既有陪伴逻辑。
- Home / End interaction / 离开页面终止所有 Worker 与设备；后台停止送帧并丢弃旧结果，返回后重新建立姿态基准。身体故障显示 **Retry body tracking**，重试不再申请摄像头。
- Demo 增加 **Lean** 和 **Arms**，保留 **Movement** 持续摇摆，可与手势、表情、声音共同验证；真实模式不读取这些模拟输入。

文档：[官方 Web 指南](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker/web_js)。模型为 `models/pose_landmarker_lite.task`，来源及 SHA-256 见 `vendor/body-manifest.json`。恢复命令：`node code/download-body.cjs`。`qa/fixtures/pose.jpg` 是 Google 官方测试照片，仅验收脚本使用，产品代码不加载它。Cloudflare Pages 输出目录仍为 `code`，需把新模型一并提交，无需修改构建命令。

### 在场、熟悉度与休息

- 旧版增长只来自表情、声音或动作的加权总和；没有任何动作时为零。现改为 Face Landmarker 持续检测到人脸就增长，不依赖 blendshape 表情分数。
- 安静在场每秒增加 0.006：从 4% 开始，约 60 秒到 40%，120 秒到 76%。微笑、轻声和温和手势可以加速；平静或悲伤不扣进度。
- 大声的散开/恢复事件与关系状态分开；即使受惊，只要仍在场，基础增长继续，不重置进度。
- 丢脸即暂停增长、保留进度。约 8 秒无人后逐渐休息，24 秒左右达到完全休息；休息仍清晰可见。回来后自然醒来，接着已有进度增长。
- 熟悉后体态更靠近、轻微主动摆动，对镜像人脸位置和手势的跟随意愿提高。姿态动作叠加在这个关系状态上，不会重置熟悉程度。
- 关系使用真实时间戳，与动画的限幅步长分离。超过一秒的陈旧识别结果停止贡献；新到场前的空白不补算。后台暂停计时，回来等待新的人脸帧。
- Demo 默认开启 **Face in view**，安静也增长；关闭以验证暂停和休息，**Face position** 可比较跟随意愿。两种模式使用同一个关系计算器。Reset 保留进度；Start fresh 和 Home 与原有行为一致，会重置熟悉度。

## 突然靠近摄像头

直接复用已有 Face Landmarker / ml5 HandPose 的同一摄像头流，不增加模型、设备申请或识别循环。人脸 Worker 多返回少量几何尺寸；主线程只计算窗口统计。依据 [Face Landmarker 的归一化关键点输出](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js)，脸部采用轮廓 234–454、10–152 的像素跨度；点属于 [官方 face oval 连接表](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/python/solutions/face_mesh_connections.py)。手部采用 5–17、0–9 的掌心跨度，忽略指尖及模型 3D 尺寸。因此仅张嘴、张手或握拳不直接改变所用的边界框。按视频实际宽高换算像素，再除以最长边，适配横竖画面与推理缩放；这估计相对尺寸变化，不测量真实米数或实际深度。

- 使用横纵跨度几何均值、对数平滑（约 .1 秒时间常数）和约 .55 秒历史窗口；低频率时窗口随实际采样间隔延长，最多约 1.05 秒。人脸要求尺寸增长 ≥16%、平均对数增长率 ≥.55/s、两个跨度各增长 ≥5.5%；掌心仍为 ≥20%、≥.65/s、各 ≥9%。窗口内至少有两次原始双轴增长，不再要求连续两次都跨过最终阈值，避免短动作在低帧率下漏掉。单次尺寸跳点后保持不动不会触发。
- 初次识别与恢复后，至少稳定在场约 .6 秒、安静约 .45 秒才准备。超过 1.2 秒的结果间隔、丢失、身份／视频比例变化、明显横移、异常尺寸或形状跳变会重新建立锚点。人脸轮廓接近图像边缘仍可参与计算，超出画面的关键点不提供证据；掌心继续检查边缘和置信度。结果延迟超过 1 秒不采用，诊断面板显示具体原因。普通缓慢靠近、轻微晃动、只增长一个跨度不满足快速靠近条件；人脸触发无需检测到手。
- 单次靠近只触发一次，冷却 3.2 秒；冷却结束后仍须停止明显增长并重新稳定，持续往前不会周期性重触发。脸和手共用新 `depth` 受惊事件的排重；它与相邻的大声／快挥手受惊也有 3.2 秒保护，避免同一次动作被多个通道连续播放。普通快挥手、突然大声触发方式仍保留，所有 Afraid 继续经过同一音效调度、优先级和冷却。
- `depth` 事件同步播放已确认的 `sounds/afraid-adjusted.wav`（.499 秒），快速而平滑地缩小整体、收拢粒子、把跟随位置拉向画面中心；光晕随之缩小，约四秒内慢慢恢复。最低可见尺寸受控，不靠变透明或闪烁表现退缩；有手／身体／声音输入时也保留核心退缩效果。表达惊讶的 `surprise` 紫色扩张通道没有复用为受惊颜色，两者可独立同时存在。熟悉程度不会因此清零。

Live 默认收起的 **Camera approach diagnostics** 显示人脸是否在场、尺寸是否可用、真实视频宽高、帧数及数据更新时间、推理延迟、原始／平滑尺寸、增长率、阈值、每项条件 PASS / WAIT、准备与共享冷却、最近受惊事件及来源、音频解码／播放状态和具体异常。**Test Afraid** 只绕过几何检测，直接调用与真实靠近相同的 `Creature.trigger('depth')`，不绕过共享冷却或 Sound Effects 开关。它使用相同事件 ID 同步驱动 `afraid-adjusted.wav` 和缩小聚拢动画；Afraid 不再有第二道音频冷却。受惊峰值暂时覆盖普通手势形态和跟随，之后平滑恢复。**Copy diagnostics** 可复制最近 30 次有效尺寸记录与当前链路状态，不含影像或录音；不能复制时可手动选择文本。报告仅保存在当前页面内存，Home 清理。

Demo 的 **Quick approach · Demo** 同样只检查事件、动画与声音，不证明摄像头检测效果。Home / End interaction 清理窗口与设备；后台暂停并重新建立锚点，迟到结果不参与计算。

自动检查：`node code/qa-approach-filter.cjs` 覆盖 4 / 8 / 12 / 20 Hz、慢靠近、抖动、持续靠近锁定、冷却与停止后重新准备、丢失／恢复、单帧跳点、单轴变化、横移、指尖张合、低置信度、边缘和不同视频尺寸。`node code/qa-approach-browser.cjs` 使用真实本地识别模型与 Chrome 虚拟设备，注入明确标记的几何序列检查动画与 .499 秒音效同步、跨脸／手排重、紫色惊讶分离、手机布局和退出清理。额外尝试本地 QA 侧脸照片裁切输入，但未获得稳定人脸，不能用它宣称真实人脸靠近已验证；识别不到时没有误触发。报告为 `qa/approach-*-report.json`。目前未完成真人在实体摄像头前的动作测试，也未实际试听。

新增 `node code/qa-afraid-debug.cjs`：不注入人脸／手部几何，使用实际 Face Landmarker 与虚拟摄像头，确认无脸状态和数据刷新；点击真正的 Test Afraid 检查 WAV 解码／调度、同一事件 ID、可见缩小聚拢、恢复、重复点击冷却、开关、退出清理、手机布局，以及人为制造的 HTTP 404 和 source.start 异常／重试。结果在 `qa/afraid-debug-report.json`。这验证浏览器软件链路，**未验证实体摄像头突然靠近、真人听感或手机硬件**。

真人测试：固定电脑／手机，建议先戴耳机，刷新页面后进入 Live，展开 **Camera approach diagnostics**。先点击 **Test Afraid**，观察明显退缩和 `Playback scheduled / Playback ended`；这些状态代表浏览器已调度，并不证明扬声器可听。若显示 `Not played`，检查同栏具体错误、Sound Effects、AudioContext 和解码状态。等待共享冷却为 Ready，再正对镜头静止至 **Face detected: Yes / Size available: Yes / Armed: Yes**，不必举手。先慢靠近，再回到原位稳定后较快靠近，观察 Growth / Speed 与各项 PASS / WAIT；持续靠近不应重复播放。若 Test 正常但靠近没有事件，在尝试后立即 Copy diagnostics 发回，利用原始尺寸记录判断是模型数据、速率、连续证据、准备条件还是共享冷却拦截。保持靠近位置不应重播，等至少 3.2 秒并停止后才可重新触发。最后做惊讶表情，应保持紫色舒展。真实弱光、侧脸、遮挡、自动变焦和不同手机仍需实测；图像尺寸无法区分数码变焦与物理靠近。

## 正式体验的 Music 与 Sound Effects

首页加载时尝试播放背景音乐；浏览器禁止自动播放时，显示英文提示，在首次点击、触摸结束或按键时重试。首页和准备页右上角有可见的 **Music** 开关；Live / Demo 面板保留独立的 **Music / Sound Effects** 开关。Music 的手动选择通过 `localStorage` 保存，换页、重新开始和刷新都不强行打开已关闭的音乐；存储不可用时仍保留当前页面的选择。效果音和设备仍只在点击 **Start interaction / Try demo** 后启动，每次体验播放一次 Wake 并同步粒子展开。原工具栏仍控制 **Microphone / Demo sound** 输入。关闭音效不会停止麦克风，关闭 Music 不会关闭效果音。

正式文件是 `sounds/wake-adjusted.wav`、`curious.wav`、`happy.wav`、`afraid-adjusted.wav`，由试听页当时确认的参数离线渲染并量化为 48 kHz / 16-bit WAV。Happy 保留最新版两次连贯起伏、默认 1.8 秒；Curious 保留 Pure 的参数和 1.2 秒时长。`sounds/approved-manifest.json` 记录哈希和参数来源；需要更新声音时，运行 `node code/tools/export-approved-sounds.cjs`（预览服务器与 Chrome `:9227` 需已启动）。原 MP3 不覆盖。

- **Wake**：每次进入体验一次，配合展开；开关关闭或音频加载失败时，视觉仍可继续。
- **Curious**：新看到手稳定约 .65 秒，或安静陪伴中熟悉度比上次探索点增加约 .12 时可触发；至少冷却 16 秒。持续同一只手不会重复触发“新看到”，离开约两秒才重新准备。
- **Happy**：微笑稳定约一秒，或熟悉度进入 .15 / .40 / .70 的新阶段时触发；至少冷却 11 秒。持续微笑只触发一次，平静两秒才重新准备。
- **Afraid**：绑定 clap 散开、快速手势 retreat 和突然靠近 depth 动画事件，使用 `sounds/afraid-adjusted.wav`，优先中断其他音效。共享处理函数以实际经过的 3.2 秒检查一次冷却，接受后用同一事件 ID 直接驱动动画与音效，音效不再另设冷却；同帧其他受惊被共享处理函数排除。遇到短暂解码／音频恢复，当前事件最多保留 350 ms 重试，成功即清除；超时、Home、后台或关闭 Sound Effects 时立即丢弃，不延迟补播。具体播放失败显示在靠近诊断面板。说话／唱歌不抑制 Afraid；手动关闭 Sound Effects 仍尊重静音选择。`node code/qa-startle-sync.cjs` 覆盖共享间隔、事件 ID 排重、短重试及取消。效果音之间不叠加，普通回应还留出约 4 秒间隔；Wake 后允许当前手势／微笑衔接。

背景声使用原文件 `sounds/waterfall.mp3`，默认输出增益 **10%（.10）**。整个页面只创建一条循环音乐轨道，首页、准备页、加载／错误页、互动页及返回 Home 均沿用同一播放位置。首次成功播放后从静音柔和渐入；效果音期间降至 .035，结束后平滑恢复至 .10。说话、唱歌、麦克风检测到声音或底噪校准均不暂停、静音或降低 BGM。降音量仅由互动音效播放触发，使用约 .07 秒的时间常数，渐入／恢复使用约 .4 秒的时间常数，避免音量跳变。效果音使用确认试听电平再乘 .65，检测到声音输入时，正在播放的普通回应平滑降至 .14；说话／唱歌期间不新增普通回应，Afraid 仍有事件优先级。Music 开关只控制背景音乐，不改变效果音或麦克风输入。

防回声措施：麦克风继续启用 echoCancellation / noiseSuppression；每次自身效果音及其后约 450 ms 内，抑制麦克风受惊判定并要求重新安静约 .4 秒才准备下一次突发。声音电平／波纹继续工作；初次校准会跳过自身 Wake，避免把它学成底噪。因此该短时间窗口内，真实大声也可能不触发受惊，快速手势仍可触发并抢占。实际扬声器、麦克风距离和设备回声处理仍需真人测试，不能用虚拟设备证明声学反馈完全消除。

返回 Home、End interaction 或取消／失败时，效果音、采集和识别立即停止；音乐继续播放，快速重新开始不重建音乐轨道。仅在 pagehide 时释放播放器和输出上下文，避免离开网站后遗留播放；晚到的效果音下载／解码结果被丢弃。切到后台暂停声音，返回后从原位置恢复音乐，不补播旧互动事件，也不覆盖 Off 选择。音乐资源失败提供英文提示和 **Retry music**；自动播放受限可点击页面解锁，互动面板也可用 **Resume sound** 重试，不阻塞识别。

自动验证：`node code/qa-audio-policy.cjs` 测试持续输入锁定、重新准备、阶段变化、优先级和回声门控；`node code/qa-playback.cjs` 实际加载四份 WAV、背景 MP3 与识别模型，用 Chrome 虚拟设备及明确注入的 RMS / 表情检查播放同步、单音轨、抢占、独立开关、麦克风输入／校准不影响 BGM、效果音降音量与恢复、反馈保护、退出／重进、资源失败与手机宽度。报告与截图为 `qa/playback-*`。现有 Demo、信号、熟悉度和 Live 生命周期检查也通过。未验证真人听感、实体手机、Safari 或真实扬声器回声。

`node code/qa-music-autoplay.cjs` 在浏览器中人为让播放返回 `NotAllowedError`，检查英文提示、首次触摸事件重试、同一播放器复用、Off 跨换页与刷新保留，以及被拦截时先关闭 Music 不会被首次交互重新打开。报告为 `qa/music-autoplay-report.json`；这验证了受限分支，不代表实际手机触摸或 Safari 自动播放策略已经实测。

真人简测：首页若未自动播放，点击或触摸空白处；确认音乐在准备页、Demo / Live 和 Home 之间连续播放。关闭 Music 后换页、刷新并重新开始，确认仍然关闭；手动打开应恢复播放。用 Demo 检查 Wake、手、微笑和 Quick wave 对应的音效；分别关闭 Music / Sound Effects，确认输入仍能驱动粒子。Live 中戴耳机试微笑、缓慢移手、安静停留；说话／唱歌时音乐应继续。再以较低扬声器音量复测，确认播放自身声音后不会连续受惊。返回 Home 检查音乐仍在、设备指示灯已停止，再进入一次确认没有双重音乐或补播旧音效。

## Cloudflare Pages

沿用已有仓库连接：Framework preset **None**，Root directory 留空，Build command **exit 0**，Build output directory **code**。生产分支需包含核心文件以及完整的 `code/vendor/`、`code/models/`、`code/sounds/`；不要只上传三个核心文件。构建监听规则也应覆盖资源子目录。

部署后从正式 HTTPS 域名打开首页，在浏览器 Network 面板确认 `.mjs`、被选中的 WASM 文件和 `.task` 返回实际文件（不是 HTML 或 Git LFS 指针），再允许设备权限。仓库中仍没有 Wrangler 配置；本次没有修改 Cloudflare 账户设置或执行线上部署。自定义 CSP 如有配置，需要允许同源资源、`worker-src 'self' blob:` 及 WASM 执行，否则请先调整 CSP。
